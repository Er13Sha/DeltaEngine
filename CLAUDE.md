# DeltaEngine — инструкции для ассистента

**Проект.** Delta Engine — верифицируемый движок понятий на логических дельтах (бинарные вилки «A / не-A» на объявленных областях определения; ответ = класс + путь + сертификат либо `UNKNOWN`). Строится с нуля: старого кода здесь нет. LLM — позже и только как непроверяемый интерфейс.

**Сначала прочитай** [docs/handoff-2026-10-27.md](docs/handoff-2026-10-27.md) (разделы 0, 2, 7, 9, 14): решения заказчика, текущий статус, что ждёт ответа. Подробности: [план](docs/delta-engine-plan.md) (что и как строится, этапы, трек E) и [спецификация](docs/delta-engine-spec.md) (требования). Если документы расходятся, главнее план и спецификация.

## Правила работы

- Отвечать по-русски.
- Сейчас режим спецификации и плана. **Код не писать без явного согласия заказчика** (старт M0 ждёт его «go»). Скелет пакетов и тест границы доверия уже есть.
- **Не коммитить и не пушить без прямой просьбы.** Репозиторий на GitHub публичный: перед любым пушем показать состав коммита.
- `private/` (экспорт Telegram-чата с именами частных лиц) в git не попадает. Не копировать его содержимое в репозиторий, не называть частных лиц в документах.
- Решения, которые принимает заказчик, задавать структурированными вопросами (рекомендованный вариант первым); остальное решать по умолчанию и сообщать.
- Оценки — честные и спокойные: что подтверждено, что гипотеза, что неверно (и для автора материалов, и для заказчика). Цифры — только измеренные, с методом.
- Новые решения заказчика дописывать в раздел 2 файла передачи контекста и в план, если они его меняют.

## Правила проекта

- `delta_kernel` — доверенное ядро: только стандартная библиотека, точная арифметика (`int`, `Fraction`), **нет `float`**, детерминизм. Проверяет `tests/architecture/test_trust_boundary.py`. Статус `verified` выдаёт только ядро с сертификатом.
- Знание делится на `Constatation` и `Hypothesis`; `Hypothesis` не может быть основанием для `Proven`. Область: `scope = model | empirical`. Результаты опытов на модели (`scope = model`) не меняют статус утверждений об эмпирической реальности.
- Реестр трека E: K1 «одноимённые электрические заряды отталкиваются» — `Constatation` (только электрический заряд); H0 (поле и частица), H1 (обобщение K1) и H2 (притяжение через экранирование) — `Hypothesis`. В правиле модели прямого притяжения быть не должно.
- Положения Катющика живут только в изолированном пакете `katyushchik_hypothesis` (`Quarantined`/`Unknown`), не в ядре.
- Критерии экспериментов записываются до запуска; отрицательные результаты хранятся наравне с положительными.
