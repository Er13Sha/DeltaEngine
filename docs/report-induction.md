# Отчёт: индуктор дельт, первые эксперименты

Дата: 26.10.2026. Код: `delta_tools/induction.py`. Повторить: `python scripts/experiments_induction.py` (около 2 минут на 4 ядрах; используется одно).

## Что сделано

Индуктор открывает вилки по размеченным примерам, как описано в разделе 7 спецификации:

- вилка создаётся только при конфликте меток в листе (минимальное различение);
- кандидаты: `a`, `a == v`, `a in {v1, v2}`, `a <= t` с точными дробными порогами, `any w in a: w == v` для множеств, `has(a)` для необязательных атрибутов, конъюнкции двух лучших кандидатов и их отрицаний;
- критерий — неоднородность Джини в точных дробях плюс штраф за размер; при равенстве решает текст предиката, поэтому результат детерминирован;
- ворота: G1 (тотальность — статически, анализом ядра), G4 (обе ветви непусты), G5 (разбиение пересчитывается ядром и сверяется с кандидатом; при дообучении примеры вне перестроенного листа не меняют класс), G6 (бюджет), G7 (вилка — гипотеза до приёмки человеком: `python -m delta_tools.review`);
- противоречивые примеры и исчерпанный бюджет дают лист `UNKNOWN`, а не «самый частый ответ»;
- дообучение по одному примеру перестраивает только затронутый лист.

## Как читать результаты

**E1** — проверка корректности индуктора, а не доказательство принципа: если данные порождены деревом вилок, индуктор его находит.

**E2** подтверждает вывод плана: на сырых признаках вилки-пороги работают не лучше обычного дерева решений, потому что это тот же класс моделей. Чтобы выйти за 0,62, индуктор должен сам строить признаки: границы периодов (2, 10, 18, 36, 54, 86) и позицию в периоде. Это следующий шаг индуктора.

**E3** показывает главное свойство подхода: модель может говорить «не знаю» там, где опора слабая, и тогда доля ошибок падает с 37 % до 14 %.

**Тип вопроса.** Обученное дерево читается как правила:

```
одно понятие и нет «и»?
├─ да → нет «к» и «у»? → нет «в» и «классификация»? → … → «что это» (22 примера)
│                                                    └─ иначе → «к какому классу»
└─ нет → нет «ли» и это не пара «объект + класс»? → «чем отличается» (20 примеров)
         └─ иначе → есть «какой»? → «к какому классу» : «относится ли» (15 примеров)
```

Почти все 16 ошибок — на словах, которые встречаются в корпусе один раз («классифицируй», «категория», «куда отнести», «опиши»). Из одного примера вилку выучить нельзя. Нужно больше настоящих вопросов, а не больше мощности.

Корпус составлен ассистентом как затравка (`data/corpora/intent_examples.json`, статус `seed_authored`), поэтому сравнение с ручным деревом не окончательное.

## Ограничения

- Индуктор пока не строит производные признаки (арифметику над атрибутами).
- Перебор кандидатов квадратичен по числу лучших кандидатов; на корпусах в миллионы слов понадобятся индексы и параллельный расчёт.
- Вилки обученного дерева — гипотезы: ответы через него получают статус «с допущениями», пока человек не примет вилки.
